# 美舰收藏（US Navy Collection）

基于《舰队收藏》核心机制复刻的**美国海军舰船拟人化网页游戏**。
数值、机制、公式全部对照 kcwiki 舰娘百科离线镜像（`../Wiki/`）复刻，再按美舰视角重做命名与编成。

- **题材**：104 艘美舰拟人化（中途岛 / 新泽西 / 企业 / 弗莱彻 / 阿拉斯加 / 射水鱼 …）
- **技术**：Node.js (Express) 静态服务 + 原生 JS 单页应用，零前端框架、零构建步骤
- **规模**：25 张海域 · 104 舰 · 115 件装备（33 类别）· 97 组敌军编成 · 69 个任务
- **质量**：三层自动化测试（引擎 / 存档迁移 / 无头浏览器 E2E）+ 战斗数值对拍基线
- **当前版本**：**V0.302**（2026-09-12，航空线）

---

## 快速开始

```bash
npm install
npm start          # 启动服务器 → http://localhost:3000
```

首次运行建议顺手建一个管理员账号（可选，用于「无限资源」测试模式）：

```bash
npm run admin      # 幂等创建 admin / admin（role=admin）
```

必须登录才能进入游戏。注册即创建账号，服务器下发 HttpOnly Cookie（7 天）免登录直进。

## V0.302 航空线（2026-09-12）

本版把「航空」从单纯的开幕空袭扩展为一条完整的可对抗链路：

- **航空战点 `mode:'air'`** — 首现于 2-3（圣克鲁斯=航母对决）。
  舰队**没有航空战力**时进入**被动防空**：敌机直接轰炸，我方仅以对空炮火还击，
  单次轰炸伤害封顶目标耐久上限 **60%**（与潜艇点同口径，**不做硬死档**）。
  三种边界分别给出不同文案：① 无航母 ② 有航母但未搭载舰载机 ③ 有航母只带舰攻（制空 0，仍走正常航空战）。
  判据与引擎起飞流程**同源**（`Battle.hasAirWing`），不另建一套「谁有航母」的算法。
- **航空触接** — 航空战结束后、炮击战前判定，成功后昼战命中 **×1.15**。
  成功率 = Σ√(机载索敌值)×5% + 制空加成（确保 +20% / 优势 +10% / 均势 0 / **制空丧失不可触接**），上限 85%；
  敌方固定 20%。走**独立字段** `_touchHit`，与索敌成功的 `_reconHit` **相乘**而非覆盖。
- **威胁维度 + 作战简报** — 21 张海域声明 `threat`（制空 / 索敌 / 对潜 / 夜战 / 电探·燃料）与 `threatNote`，
  **必须能由该图节点推导**，测试做双向校验防剖面漂移；11 张海域有 `brief` 作战简报。
- **编成自检（出击前情报室）** — 海域选择页展示 舰队能力 / 士气 / 威胁对位 / 航向侦察 / 航空触接 / 特殊攻击 / 威胁评估，
  与战斗引擎**同源**（UI 不另写算法）。**只提示、不拦截出击**。
- **舰历与战功** — 每舰 `record`（出击 / 击沉 / 大破等舰史）、`record.objectives` 战功；14 个作战目标分布在 8 张图，
  纯判定、不改战斗数值。49 艘舰有史实 `bio`。
- **失败归因** — 战斗失败后按 制空不足 / 索敌失败 / 夜战不利 / 对潜不足 给出可操作的编成建议（纯函数 `attributionLines()`）。

存档版本 **v5**，旧档自动迁移。

## 立绘系统

三级回退链：**分层立绘 → 单张 AI 立绘 → 程序化 SVG 占位 → 舰种占位符**。

1. **SVG 占位**（`public/art/portraits/`，106 张）：程序化生成，`npm run art` 重生成。
2. **AI 立绘**（`public/art/ai/`）：`npm run art-ai` 调用智谱 CogView 生成；
   `index.json` 映射 `shipId`（改造态 `_kai` / `_kai2`）→ 文件名。
   **新增舰娘立绘只需「丢图进目录 + 加一行映射」，不用改代码。**
3. **分层立绘 / 近似 Live2D**（`public/art/live2d/<id>/`）：语义分层素材，支持呼吸、视线跟随、触碰交互。
   驱动在 `js/ui/secretary-live2d.js`（`SecretaryL2D.has/html/bind`），幅度参数在同文件 `CFG`。

立绘制作工程在独立的 `../ArtPipeline/`（不放进本仓库，避免大图撑爆 git 历史）。

> 分层素材的生产有两条硬约束，记录在此避免重走：
> ① **脖子必须 100% 跟随头部**（刚性变换下"少转"等于"脱节"，下巴与脖子之间会裂开）；
> ② **各层 `transform-origin` 必须换算到自身坐标系**（`原点 - 层的 left/top`），用百分比必错，因为各层尺寸不同。
> 另外：**任何"纯分割"式的分层都撑不住形变** —— 必须用 inpaint 补画被遮挡区域，让相邻层在接缝处有重叠的完整内容。

**当前基线：1581 + 32 + 186 全部通过，E2E 0 个 JS 错误。**

### 对拍基线（为什么需要它）

战斗含大量随机数消费，改动一处就可能让整条随机数流错位，用「跑两次 sim 肉眼比数字」根本发现不了。
`scripts/drift_check.js` 用**固定种子 LCG + 9 组战斗场景 + 日志指纹**把结果哈希化，与基线**逐位比对**：

- `scripts/battle_digest.baseline.txt` —— 当前版本基线
- `scripts/battle_digest.baseline_v0301.txt` —— V0.301 存档基线

新增任何**会消耗随机数**的机制，都要给它一个 `opts.xxx === false` 开关，并保证关掉后能**逐位回到上一版基线** ——
这是「除新增机制外其余逻辑一位未动」的硬证明手段。**改战斗代码前后必跑。**

### E2E 与负向对照

E2E 覆盖登录 / 母港 / 编成 / 建造 / 出击 / 图鉴等真实 DOM 流程，失败返回非零退出码，可直接接入 CI。
UI 相关断言（如布局位置）会额外做**负向对照**：故意把改动还原成错误形态，确认断言真的变红，
避免写出"怎么改都绿"的空转断言。

## 账号与登录

- 必须登录才能进入游戏；注册即创建新账号
- 登录/注册后服务器下发 **HttpOnly Cookie**（`usnc_session`，7 天），关闭浏览器后免登录直进
- 登录页可勾选「记住账号和密码」，仅用于下次回填表单（明文存于浏览器 localStorage）
- 「无限资源」按钮仅管理员（`admin`）可见可用，普通账号/游客即使改本地缓存也无法生效
- 首次以无存档账号登录时，会自动带走浏览器中遗留的旧游客存档作为初始档

## 账号 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/auth/register` | 注册 `{username, password}` → `{token, role, save}`（保留名 `admin` 不可注册） |
| POST | `/api/auth/login` | 登录 → `{token, role, save}`，并下发 Cookie |
| POST | `/api/auth/logout` | 退出（Bearer token 或 Cookie），同时清除 Cookie |
| GET | `/api/save` | 取档（Bearer token 或 Cookie 免登录）→ `{username, role, save}` |
| PUT | `/api/save` | 存档 `{save}`（Bearer token 或 Cookie） |

密码以 `scrypt` 加盐哈希存储于 `data/users.json`（含 `role` 字段）；会话为内存 token（7 天）；`data/` 目录不入库。

## 存档

- 同步到服务器 `data/saves/<用户名>.json`（浏览器保留本地缓存兜底），每 5 秒自动保存 + 切页保存
- 服务器重启后 Cookie 会话失效，需重新登录
- 想重开：删除服务器 `data/saves/<用户名>.json`，并清掉 `data/users.json` 中对应条目

## 养成系统速查（参照 kcwiki）

- **近代化改修（合成）**：舰娘详情 → 近代化改修，最多选 5 艘素材舰。素材值由舰种 / 改造形态决定，奖励与偏斜各 50%（奖励值 =(n+1)÷5+n），素材合计 +4/+9/+14/+19/+24 额外奖励点。上限：火力 / 雷装 / 对空 / 装甲 = 基础 ×1.3；海防舰素材可喂 耐久 +2 / 对潜 +9 / 运 +8（改造后继承）。改造会重置 火力 / 雷装 / 对空 / 装甲 的改修值。
- **装备开发**：消耗 燃料 / 弹药 / 钢材 / 铝（必消耗）+ 开发资材（成功才消耗，失败返还）。秘书舰系（炮战 / 水雷 / 空母 / 潜水）与最高资源共同决定 9 个开发池之一；每池 50 等份、出货率 = 份额 ×2%；roll 出装备后需 提督等级 ≥ 稀有度 ×3 且四项资源 ≥ 最低要求（= 解体回收值 ×10）才成功。开发资材初始 10，日常任务 +1/天，上限 3000。
- **装备解体与仓库**：工厂「装备仓库」页签按类别分组一览全部装备（★ / 锁定 / 装备中状态），解体回收资源（装备中 / 上锁不可解体）。
- **装备改修工厂**：需要工作舰「维斯塔尔」担任秘书舰（一次性任务「舰队之母」获得）。消耗改修资材（螺丝）+ 资源强化装备 ★。每日次数 1~3（二号舰工作舰 / 水母 +1，维斯塔尔改 +1）；★+4 前必成功，之后按 wiki 成功率表；「确定化」消耗双倍螺丝必定成功；★+6 起需同名 ★0 装备作素材；★MAX 后可更新进化。改修效果 = 类别系数 × √★（大主炮 1.5 / 鱼雷 1.2 / 其余 1.0）。
- **改修资材（螺丝）**：日常「装备的改修强化」+1/天，周常 / 月常更多；上限 3000。

## 时间缩放说明

为适配网页游戏的会话节奏，所有游戏时间按比例压缩：

- **远征**：配置分钟数 = 现实秒数（15 分钟远征 = 15 秒，12 小时远征 = 12 分钟）
- **建造**：1 小时 = 现实 60 秒（4.5 小时空母 ≈ 4.5 分钟）
- **资源恢复**：每 30 秒 +3/+3/+3/+1（油/弹/钢/铝）。原版每 3 分钟 油弹钢 +3 铝 +1，按 6 倍压缩；自然恢复上限 =（提督等级 +3）×250。离线期间补算。
- 管理员顶栏「测试模式」：无限资源 + 瞬间建造完成 + 瞬间入渠完成
