# 美舰收藏（US Navy Collection）

基于《舰队收藏》核心机制复刻的**美国海军舰船拟人化网页游戏**。
数值、机制、公式全部对照 kcwiki 舰娘百科离线镜像（`../Wiki/`）复刻，再按美舰视角重做命名与编成。

- **题材**：104 艘美舰拟人化（中途岛 / 新泽西 / 企业 / 弗莱彻 / 阿拉斯加 / 射水鱼 …）
- **技术**：Node.js (Express) 静态服务 + 原生 JS 单页应用，零前端框架、零构建步骤
- **规模**：25 张海域 + **4 场历史战役** · 104 舰 · 115 件装备（33 类别）· 117 组敌军编成 · 69 个任务 · 远征编成条件 7/8 · **图鉴获取途径全览 + 军需处（战功章）**
- **质量**：三层自动化测试（引擎 / 存档迁移 / 无头浏览器 E2E）+ 战斗数值对拍基线
- **当前版本**：**V0.306**（2026-09-16，海域难度评级 + 支援舰队 + 运输作战）

---

## 快速开始

```bash
npm install
npm start          # 启动服务器 → http://localhost:3000
```

首次运行建议顺手建一个管理员账号（可选，用于「无限资源」测试模式）：

```bash
npm run admin      # 幂等创建 admin / admin（role=admin）
```

必须登录才能进入游戏。注册即创建账号，服务器下发 HttpOnly Cookie（7 天）免登录直进。

## V0.305 图鉴深化 + 军需处（2026-09-14；2026-09-15 评审整改）

**给游戏里那堆"只读的成就"接上出口。** 本版第一次做**货币**：把高难内容的产物换成可支配的战功章。
预期**零 `battle.js` 引擎改动** —— drift 三基线全程逐位一致就是本版本的验收项。

> ⚠️ **评审整改（2026-09-15）**：交付评审判 **CONCERNS / 1 条 P0** —— 本版唯一的**可重复**章产出源
> 「每周首次史实重演 S 胜 +1」**自第二周起永不发放**（把 V0.303 的一次性账本标记当成了周期性触发条件），
> 军需处因此会退化成"换完即止的毕业清单"。已修 + **红绿验证**（缺陷形态下恰好 3 条新断言变红），
> 并补齐**集成层断言**（`Sortie.start → prepareBattle → settleBattle` 真实链路，禁止喂 flag）。
> 详见 `design/评审_V0.305_整改说明.md`。**教训：新的绿不等于新的对 —— 跨模块机制必须有集成层断言。**

### 图鉴深化（收集端）

- **获取途径可见化（零新增数据）** — 新模块 `public/js/game/acquisition.js` 从既有数据派生"去哪拿"：
  道中掉落 / BOSS 掉落 / **战役 BOSS 掉落** / 可建造 / 任务奖励 / 初始赠送（舰船），
  开发池（秘书舰系 × 资源池）/ 改修更新（★MAX 进化）/ 随舰自带 / 任务奖励 / 战役奖励（装备）。
  未登录卡片**仍显示「？？？」**（收集悬念不破），点开只给途径 —— 图鉴从"纪念册"变成**出击决策的索引**。
  `Acquisition.unimplemented()` 顺带暴露一个真实的既有缺口：**6 件装备没有任何产出渠道**
  （`xf5u` / `fr1` / `fleetcom` / `repair_facility` / `crew_vet` / `m4a1`，V0.302~V0.304 遗留，本版范围冻结不补），
  因此**装备收集率 100% 不可达** —— 这正是里程碑最高档只给纪念荣誉的实证依据。
- **详情页三态** — 有实例 → 复用 `Homeport.openShipDetail`（属性/装备/舰历三合一）；
  已解体（图鉴仍登录）→ 只读降级面板（基础属性 + 装备槽 + 舰史 + 途径）；
  未获得 → 途径弹窗。**坑 #35**：`recordPane` 读的是实例，图鉴看的是"曾经获得过的 id"，两者数据源不同。
- **收集率里程碑** — 舰船 / 装备两条线各 25% / 50% / 75% 三档，各给 **+2 战功章**（自动发放、账本幂等）；
  **100% 只给纪念性荣誉**（`codex_ships_full` / `codex_equips_full`，`check` 恒 false、永不参与战斗结算）。
  **坑 #36**：档位按 `owned / total` 百分比判定，绝不写死绝对数（`libraryStats().total` 是动态的）。

### 军需处（消费端）

- **战功章（存档 v7）** — `st.stats.medals` 余额 + `st.stats.medalLedger = { once:{}, weekly:{} }`。
  产出记账一律「**查账本 → 记账 → 加余额**」（坑 #31：同一次结算被多个路径打到也只发一次）。
- **产出源 7 类** — 海域首通 +1 / 作战目标 +1 / 战役 常规阶首通 +2 · 史实重演 +2 · 强敌阶首通 +3 /
  图鉴里程碑 +2 / **每周首次「史实重演」S 胜 +1**。
  设计张力（规划方案 §4.3）：一次性成就总量有限，**必须保留一条每周 1 枚的可重复产出**，
  否则军需处会退化成"换完即止的毕业清单"。每周项与周常重置读**同一个 `periodKeys()`**（坑 #32）。
- **唯一调用点** — `sortie.js::settleBattle()` 里一次算清本场的全部章产出，**并写进战报**
  （`战功章 +2（H1 史实重演）`）—— 不许静默发放。
- **兑换表** — 应急修理要员 2 / 洋上补给 3 / 战斗粮食 1（不限购）+ 改修资材×5 2 / 开发资材×5 1（每周限 1）。

- **独立导航屏 `medals`** — 「司令部」组新增一级菜单（与图鉴并列），顶栏资源条显示章余额；
  屏幕含 兑换区（限购状态 + 余额不足/仓库满的**禁用理由**）与 **产出记录**（遍历 `MEDAL_SOURCES`，
  显示每类来源的已领/总量与本周状态）。
- **编成预设（批次 3）** — 存**舰船 id**而非 uid；载入时从未编入其他舰队的实例里挑（优先未上锁、等级高），
  **缺员时明确报出缺哪几艘**，不静默少载。

`normalizeSave` 依然不补新键（坑 #30：补了就绕过迁移器，迁移测试变空转 —— 本版有专门的反向断言守着）。

## V0.302 航空线（2026-09-12）

本版把「航空」从单纯的开幕空袭扩展为一条完整的可对抗链路：

  敌方固定 20%。走**独立字段** `_touchHit`，与索敌成功的 `_reconHit` **相乘**而非覆盖。
- **威胁维度 + 作战简报** — 23 张海域声明 `threat`（制空 / 索敌 / 对潜 / 夜战 / 电探·燃料）与 `threatNote`，

## 立绘系统

三级回退链：**分层立绘 → 单张 AI 立绘 → 程序化 SVG 占位 → 舰种占位符**。

1. **SVG 占位**（`public/art/portraits/`，106 张）：程序化生成，`npm run art` 重生成。
2. **AI 立绘**（`public/art/ai/`）：`npm run art-ai` 调用智谱 CogView 生成；
   `index.json` 映射 `shipId`（改造态 `_kai` / `_kai2`）→ 文件名。
   **新增舰娘立绘只需「丢图进目录 + 加一行映射」，不用改代码。**
3. **分层立绘 / 近似 Live2D**（`public/art/live2d/<id>/`）：语义分层素材，支持呼吸、视线跟随、触碰交互。
   驱动在 `js/ui/secretary-live2d.js`（`SecretaryL2D.has/html/bind`），幅度参数在同文件 `CFG`。

立绘制作工程在独立的 `../ArtPipeline/`（不放进本仓库，避免大图撑爆 git 历史）。

> 分层素材的生产有两条硬约束，记录在此避免重走：
> ① **脖子必须 100% 跟随头部**（刚性变换下"少转"等于"脱节"，下巴与脖子之间会裂开）；
> ② **各层 `transform-origin` 必须换算到自身坐标系**（`原点 - 层的 left/top`），用百分比必错，因为各层尺寸不同。
> 另外：**任何"纯分割"式的分层都撑不住形变** —— 必须用 inpaint 补画被遮挡区域，让相邻层在接缝处有重叠的完整内容。

### 对拍基线（为什么需要它）

战斗含大量随机数消费，改动一处就可能让整条随机数流错位，用「跑两次 sim 肉眼比数字」根本发现不了。
`scripts/drift_check.js` 用**固定种子 LCG + 战斗场景 + 日志指纹**把结果哈希化，与基线**逐位比对**：

- `scripts/battle_digest.baseline.txt` —— 当前版本基线（12 组场景）
- `scripts/battle_digest.baseline_v0302.txt` —— V0.302 存档基线（9 组常规场景）
- `scripts/battle_digest.baseline_v0301.txt` —— V0.301 存档基线

新增任何**会消耗随机数**的机制，都要给它一个 `opts.xxx === false` 开关，并保证关掉后能**逐位回到上一版基线** ——
这是「除新增机制外其余逻辑一位未动」的硬证明手段。**改战斗代码前后必跑。**

> ⚠️ 行尾陷阱（2026-09-13 实测）：本机 `core.autocrlf=true`，若基线文件被 `git checkout/restore` 重新落盘，
> 行尾会由 LF 变 CRLF，逐行比对时行尾 `\r` 会造成**三基线全文件误报漂移**（哈希其实完全一致）。
> `drift_check.js` 已内置行尾归一化；若仍见整文件漂移，先确认基线文件行尾是否为 LF。

### E2E 与负向对照

E2E 覆盖登录 / 母港 / 编成 / 建造 / 出击 / 图鉴等真实 DOM 流程，失败返回非零退出码，可直接接入 CI。
UI 相关断言（如布局位置）会额外做**负向对照**：故意把改动还原成错误形态，确认断言真的变红，
避免写出"怎么改都绿"的空转断言。

## 账号与登录

- 必须登录才能进入游戏；注册即创建新账号
- 登录/注册后服务器下发 **HttpOnly Cookie**（`usnc_session`，7 天），关闭浏览器后免登录直进
- 登录页可勾选「记住账号和密码」，仅用于下次回填表单（明文存于浏览器 localStorage）
- 「无限资源」按钮仅管理员（`admin`）可见可用，普通账号/游客即使改本地缓存也无法生效
- 首次以无存档账号登录时，会自动带走浏览器中遗留的旧游客存档作为初始档

## 账号 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/auth/register` | 注册 `{username, password}` → `{token, role, save}`（保留名 `admin` 不可注册） |
| POST | `/api/auth/login` | 登录 → `{token, role, save}`，并下发 Cookie |
| POST | `/api/auth/logout` | 退出（Bearer token 或 Cookie），同时清除 Cookie |
| GET | `/api/save` | 取档（Bearer token 或 Cookie 免登录）→ `{username, role, save}` |
| PUT | `/api/save` | 存档 `{save}`（Bearer token 或 Cookie） |

密码以 `scrypt` 加盐哈希存储于 `data/users.json`（含 `role` 字段）；会话为内存 token（7 天）；`data/` 目录不入库。

## 存档

- 同步到服务器 `data/saves/<用户名>.json`（浏览器保留本地缓存兜底），每 5 秒自动保存 + 切页保存
- 服务器重启后 Cookie 会话失效，需重新登录
- 想重开：删除服务器 `data/saves/<用户名>.json`，并清掉 `data/users.json` 中对应条目
